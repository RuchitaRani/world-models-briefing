Dreamer V1, step by step

How the agent from Dream to Control (Hafner et al., ICLR 2020) learns to make a cheetah run from pictures alone: play a little for real, then practice a lot in its own imagination.

01The parts: world vs. agent

There are two sides. The environment is the game: a physics simulator holding the cheetah. The agent is the brain that plays it. The agent cannot look inside the game. It never sees joint angles or speeds, only a small 64×64 picture and one score number after every move.

PartBelongs toJob in one line
Encoder (eyes)World modelTurns a 64×64 image into a list of numbers e
GRU memoryWorld modelCarries the story so far as 200 numbers h
Prior (eyes closed)World modelGuesses the moment z from memory only, no image
Posterior (eyes open)World modelWorks out z from memory plus the image
DecoderWorld modelRedraws the image from the summary. Used only while studying
Reward modelWorld modelGuesses the score of one moment
ActorSeparate networkReads the summary, outputs the 6 pushes
Critic (value model)Separate networkGuesses the total future score from a moment
Diary (replay buffer)Stored dataKeeps every real try forever

The summary of a moment is s = (h, z): 200 memory numbers plus 30 "what's happening now" numbers, about 230 in total. Everything the agent knows about the cheetah at a moment is squeezed into these numbers.

02The master loop

This is the whole program from start to finish. One round is 100 study-and-dream updates followed by one real try. The paper runs roughly 1,000 rounds (about one million simulator frames).

03The diary (replay buffer)

The diary starts empty. During each try, one row is written per step. When the try ends, its 500 rows are saved together as one file in a folder on disk (a compressed NumPy file in the authors' code, roughly 6 MB), and loaded into RAM so clips can be cut quickly.

  • Image: 64 × 64 pixels × 3 colours = 12,288 whole numbers from 0 to 255.
  • Push: 6 decimals between −1 and +1, one per leg joint.
  • Score: 1 decimal between 0 and 1. The simulator computes it from a formula the task designers wrote (roughly "faster forward = higher"). The agent only ever receives the number.

The diary never stores summaries, memory, or dreams. Those are recalculated with the newest world model every time, so they are never out of date.

04Real play (one try)

This is the only time the agent touches the real game. It happens 5 times with random pushes at the very start, then once per round with the actor. Each step:

  1. The simulator shows an image.
  2. The encoder turns it into numbers, the GRU updates the memory h, and the posterior works out z. That gives the summary s.
  3. The actor reads s and outputs 6 pushes.
  4. A small random number is added to each push (spread 0.3), so the cheetah tries slightly new moves. For example, 0.50 becomes 0.62.
  5. The simulator applies the push for 2 ticks, then returns a new image and score.
  6. The row (image, push, score) is written down. After 500 steps the try is saved to the diary.

No network learns during real play. Memory h starts at zero when the try begins and is thrown away when it ends.

What "repeat each action for 2 ticks" means

05Study: how the world model learns

Take one batch of 50 clips. For each clip, memory starts at zero and the model walks through the 50 steps in order. At every step it does the following. All 50 clips run side by side on the GPU.

The three comparisons

#ComparesWithWhat it teaches
①Redrawn imageReal image (diary)The summary must hold everything visible: leg positions, tilt, height
②Guessed scoreReal score (diary)The reward model learns which moments score well
③Eyes-closed zEyes-open zThe prior learns to predict without pictures, which is what makes dreaming possible

How "eyes closed" and "eyes open" work. They are two small networks. Both receive the same memory h. Only the posterior also receives the image numbers e. Each outputs 30 best values plus 30 "how unsure" values (a Gaussian). Comparison ③ measures how different the two are (the KL divergence) and nudges both toward each other. If they are already within 3 "free nats", no nudge is applied.

For one of the 30 numbersBest valueUnsure by
Eyes closed (prior)0.40± 0.30
Eyes open (posterior)0.55± 0.05
Why the decoder exists. It is a teacher for the world model, not something a human needs. If 230 numbers can redraw the whole picture, they must contain the important facts. The decoder is used only while studying, never in dreams or real play.

06Dream: how the actor and critic learn

Right after studying, in the same update, the world model is frozen. Every one of the 2,500 eyes-open summaries from the batch becomes the starting point of a 15-step dream. The 2,500 summaries are stacked into one table of 2,500 rows, and the GPU runs every row at the same time.

The real settings are 15 steps, λ = 0.95 and γ = 0.99 (future scores count slightly less). The blend trusts the guessed scores for the near future and hands over to the critic for the far future, so the agent cares about more than 15 steps ahead.

The actor's output. For each of the 6 joints it gives a best push and how unsure it is. A random value is drawn near the best push and squashed into −1…+1 with tanh. In real play the best push is used, plus exploration noise. For Atari games the actor instead gives a probability for each button.

How the GRU "stores" memory

The GRU has no special storage. Its memory is a list of 200 numbers held in ordinary computer memory, like any variable. Every step it computes new h = GRU(old h, last z, last push) and overwrites the old numbers. Gates inside decide how much of the old story to keep and how much to replace. The knowledge of how to remember is in the GRU's weights, which are kept. What it currently remembers is h, which is overwritten every step.

08The full algorithm

Plain-language version, with the paper's names in brackets.

// setup diary ← 5 tries with random pushes [S = 5 seed episodes] world model θ, actor φ, critic ψ ← random weights repeat for about 1,000 rounds: repeat 100 times: [C = 100 updates] // A. study: world model learns batch ← 50 clips × 50 steps cut from random tries [B = 50, L = 50] for each clip, memory h ← 0 for step t = 1 … 50: h ← GRU(previous h, previous z, real push) prior ← guess z from h [transition q(s_t | s_t-1, a_t-1)] e ← encoder(real image) z ← posterior from h and e [representation p(s_t | s_t-1, a_t-1, o_t)] image' ← decoder(h, z) [observation q(o_t | s_t)] score' ← reward model(h, z) [reward q(r_t | s_t)] error ← (image' vs image) + (score' vs score) + KL(posterior ‖ prior), ignoring KL below 3 nats adjust θ to reduce error [Adam, lr 6e-4] // B. dream: actor and critic learn (θ frozen) starts ← all 2,500 summaries (h, z) from step A, detached for dream step τ = 1 … 15: [H = 15] push ← actor(summary) [q(a_τ | s_τ), tanh Gaussian] summary← prior imagines next (h, z) score' ← reward model(summary) value ← critic(summary) [v(s_τ)] target ← λ-return from scores and values [V_λ, γ = 0.99, λ = 0.95] adjust φ to make Σ target bigger [backprop through the dream] adjust ψ toward target (target held fixed) [½(v − V_λ)²] delete batch, summaries, dreams // C. real play: one try h ← 0, image ← simulator.reset() for step t = 1 … 500: summary ← encoder + GRU + posterior(image) push ← actor's best push + Normal(0, 0.3) noise image, score ← simulator.step(push) for 2 ticks [action repeat R = 2] write (image, push, score) diary ← diary + this try
